FARM ADVISORY PROJECT - COMPLETE DETAILS
========================================

1. PROJECT OVERVIEW
-------------------
Project name: Farm Advisory / Agriculture Helper

Farm Advisory is a web application designed to help farmers obtain useful
information about crops, soil types, fertilizers, market prices, weather,
trading, and general farming practices. It provides separate farmer and
administrator dashboards.

The project uses a Python Flask backend. HTML pages provide the user interface,
CSS provides styling, and JavaScript embedded in the HTML pages provides
interactive browser features.


2. LANGUAGES AND TECHNOLOGIES USED
----------------------------------

A. Python
   Purpose:
   - Runs the backend web server.
   - Defines all website routes and API endpoints.
   - Handles registration, login, logout, and sessions.
   - Controls farmer and administrator permissions.
   - Stores and processes crop, soil, fertilizer, market, order, user, and
     farmer-query data.
   - Renders HTML templates and returns JSON API responses.

   Main Python file:
   - python/app.py

B. Flask
   Purpose:
   - Flask is the Python web framework used by the application.
   - It connects browser URLs to Python functions.
   - It renders the HTML templates in the html folder.
   - It serves files from the css and images folders.
   - It manages form submissions, redirects, flash messages, and sessions.

   Version:
   - Flask 2.3.3

C. Werkzeug
   Purpose:
   - Werkzeug provides the underlying WSGI and web utilities used by Flask.

   Version:
   - Werkzeug 2.3.7

D. MySQL
   Purpose:
   - Provides persistent storage for users, crops, soils, fertilizers, market
     data, transactions, and farmer inquiries.
   - The farm_advisory database and its tables are created automatically by
     python/init_db.py or when python/app.py starts.
   - mysql-connector-python connects the Flask backend to MySQL.

E. HTML5
   Purpose:
   - Builds the structure and content of all web pages.
   - Contains forms, navigation bars, cards, tables, dashboards, and page
     content.
   - The HTML files are Flask/Jinja templates, so they can display dynamic
     values supplied by Python.

   Location:
   - html/

F. Jinja Template Language
   Purpose:
   - Displays Python data inside HTML pages.
   - Uses expressions such as {{ crop.name }} and control structures for loops
     and conditions.
   - Creates dynamic crop, soil, fertilizer, market, cart, dashboard, and admin
     content.

G. CSS3
   Purpose:
   - Controls colors, fonts, spacing, page layout, cards, buttons, dashboards,
     tables, and responsive presentation.
   - The project contains external CSS files and additional page-specific CSS
     embedded inside the HTML templates.

   Files:
   - css/css1.css
   - css/style.css

H. JavaScript
   Purpose:
   - Provides browser-side interactivity.
   - Supports actions such as dynamic searching, crop-finder behavior, chart
     display, form interactions, and dashboard controls.
   - JavaScript is currently embedded in the HTML templates rather than stored
     in a separate JavaScript file.

I. JSON
   Purpose:
   - The /api/search endpoint accepts JSON search requests and returns JSON
     results.
   - JSON is a data format used by the API, not a separate application file.

J. Windows Batch Script
   Purpose:
   - run.bat installs the required Python packages and starts the Flask server
     on Windows.

K. Markdown and plain text
   Purpose:
   - README.md documents the project and setup instructions.
   - database/README.md explains the database folder.
   - requirements.txt lists the required Python packages.
   - PROJECT_DETAILS.txt contains this complete project description.

L. External browser resources
   - Google Fonts are used by some pages.
   - Chart.js is used by the trading page for charts.
   - Some page backgrounds and icons are loaded from Unsplash and other image
     content-delivery websites.

7. DATA AND DATABASE DETAILS
----------------------------

The application uses a persistent MySQL database named farm_advisory by default.

Database tables:
   - users
   - crops
   - soils
   - fertilizers
   - market_data
   - transactions
   - farmer_queries

Database-related files:
   - python/database.py contains connections and database operations.
   - python/init_db.py creates and verifies the database.
   - database/schema.sql defines all tables and indexes.
   - database/seed.sql inserts initial demo and reference data.
   - .env.example documents the required connection settings.

All registrations and dashboard changes now persist after the Flask server is
restarted. MySQL passwords are supplied through the ignored .env file and user
passwords are stored as password hashes.

9. HOW THE PROJECT WORKS
------------------------

1. The user runs python/app.py directly or starts run.bat.
2. Flask creates the web application.
3. Flask reads templates from the html folder.
4. Flask serves stylesheet files from css and images from images.
5. The browser requests a route such as /login or /crops.
6. The related Python route function processes the request.
7. Python passes any required data to a Jinja HTML template.
8. Flask returns the rendered page to the browser.
9. Forms send data back to Flask using GET or POST requests.
10. Flask updates the in-memory data and redirects or returns a response.


10. INSTALLATION AND RUNNING IN POWERSHELL
------------------------------------------

Open PowerShell in the repository root:

   C:\Users\Admin\Desktop\farm advisory\farm-advisory-

Create a virtual environment:

   python -m venv .venv

Activate it:

   .\.venv\Scripts\Activate.ps1

If PowerShell blocks activation, run:

   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Then activate the environment again.

Install dependencies:

   python -m pip install -r requirements.txt

Create the private environment file:

   Copy-Item .env.example .env
   notepad .env

Enter the correct MySQL username and password, then create the database:

   python python\init_db.py

Start the application:

   python python\app.py

Alternative Windows command:

   .\run.bat

Open this address in a browser:

   http://127.0.0.1:5000

Stop the server with:

   Ctrl+C

12. DEVELOPMENT AND PRODUCTION NOTES
------------------------------------

Current development behavior:
   - Flask debug mode is enabled when python/app.py runs directly.
   - The application uses Flask's local development server.
   - MySQL provides persistent application storage.
   - Database and Flask secrets are read from the private .env file.
   - Passwords created through the application are hashed.

Recommended future improvements:
   - Add formal migration tooling such as Alembic.
   - Add connection pooling for larger production workloads.
   - Add CSRF protection and stronger input validation.
   - Move embedded JavaScript into a dedicated JavaScript folder.
   - Move embedded page styles into the css folder.
   - Add automated unit and integration tests.
   - Use a production WSGI server when deploying publicly.
   - Add weather data through a reliable weather API.
